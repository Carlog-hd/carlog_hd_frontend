# CARLOG IVI 디자인 개편 진행 계획

## 기준과 범위

- 기준 브랜치: `main`의 현재 상태 (`44543dd`, 원격보다 로컬 커밋 2개 앞섬)
- 디자인 참고: 사용자 제공 `CARLOG_IVI_목업 (1).html`
- 구현 앱: `ivi/app`의 네이티브 Android 프로젝트
- HTML은 시각·화면 흐름 참고 자료다. 차량 SDK, 서버, 실제 차량 데이터 연동은 시안에 포함된 것으로 간주하지 않는다.
- 기존 주행 시뮬레이션과 운전 중 조작 제한은 유지한다.

## 화면 이름 대응안

| HTML 목업 | 기존 Android 앱 | 개편에서 할 일 |
|---|---|---|
| 홈 | 홈 | 대시보드 구조와 색/타이포를 목업 기준으로 맞춘다. |
| 발견 | 코스 | 공개 피드와 추천 코스 표현을 검토하고, 기존 코스 선택·안내 기능을 보존한다. |
| 기록 | 주행 | 기록 목록/상세와 현재 주행 화면의 진입 구조를 설계한다. |
| 도감 | 칭호 | 명칭과 카드/수집 표현을 맞추고 현재 획득 상태를 유지한다. |
| MY | MY | 목업의 프로필 및 설정 카드와 현재 구현 범위를 대조한다. |

## 구현 순서

1. **현행 화면과 목업 대조**: Android 화면별 레이아웃·상태·동작을 확인하고, 목업 요소를 재사용/변경/제외로 분류한다. 특히 주행 중 가능한 조작과 정차 시 가능한 조작을 나눈다.
2. **공통 디자인 기반**: 색상, 글자 크기, 여백, 모서리, 카드/버튼 상태를 공통 리소스와 스타일로 정리한다. 기존 레이아웃 체계에 맞춰 작은 단위부터 반영한다.
3. **앱 셸과 메뉴**: 좌측 메뉴, 상단 차량 상태, 콘텐츠 영역을 목업의 밀도와 계층에 맞춘다. Android의 기존 화면/동작 연결은 보존한다.
4. **홈**: 요약 카드, 최근 드라이브, 대표 칭호, 코스 진입을 개편한다.
5. **발견/코스**: 목업 피드형 카드와 분류 탭을 반영하되, 기존 샘플 코스 저장 및 안내 시작과 이어지게 한다.
6. **기록/주행**: 기록 목록·상세로 이동하는 구조와 주행 세션 상태를 구분한다. 주행 중 편집·탐색 제한을 유지한다.
7. **도감/칭호 및 MY**: 목업의 수집/프로필 카드 표현을 적용하고 현재 동작하는 상태만 표시한다.
8. **마감**: 대표 IVI 화면 크기에서 잘림·스크롤·터치 영역을 확인하고, 기능 연결과 문서 상태를 정리한다.

## 완료 기준

- 다섯 메뉴의 시각적 언어가 첨부 시안과 일관된다.
- 화면 전환, 코스 저장/안내, 주행 시뮬레이션 및 기존 기록/칭호 동작이 유지된다.
- 주행 중 영상 편집/피드 게시 같은 목업 상호작용을 차량 앱에 무비판적으로 옮기지 않는다.
- 실제 API/차량 SDK가 연결되지 않은 정보는 샘플 상태로 표시한다.

## 첫 구현 단위

1단계의 화면 대조표를 먼저 만들고, 그 표에서 공통 디자인 기반과 앱 셸 작업을 확정한다. 이후 각 메뉴를 한 단계씩 구현해 변경 범위를 검토하기 쉽게 유지한다.

## 2026-11-14 진행 상태

- 완료: 목업의 홈 문구·최근 드라이브 커버/요약·드라이버 요약·추천 코스 카드로 홈을 재구성했다. 최근 저장 기록이 있으면 실제 로컬 기록을 표시하고 상세로 연결한다.
- 완료: 왼쪽 `주행` 메뉴를 `기록`으로 바꾸고 저장된 드라이브 목록과 새 주행 시작 화면을 추가했다. 시뮬레이션 중에는 기존 주행 화면으로 바뀌며 다른 메뉴 이동을 제한한다.
- 완료: 발견 코스를 3열 카드로 정리하고, 도감·MY 제목을 목업 문구에 맞췄다. MY에 드라이버 프로필 요약을 추가했다.
- 확인: `:app:assembleDebug` 빌드 성공. 이후 PLEOS Connect 에뮬레이터에서 다섯 메뉴의 실제 표시를 확인했다.
- 다음: 차량용 범위에 맞는 모먼트 타임라인과 테마 연동을 단계적으로 확장한다.
- 추가 완료: 기록 화면에 최근 드라이브를 바탕으로 한 4장면 스토리 미리보기와 이전/다음 조작을 연결했다. 실제 영상 파일 생성은 기존 범위대로 미연동이다.
- 개발 환경: Android Studio에서 `ivi/`를 프로젝트로 열 때 Git 루트는 부모 worktree다. `ivi/.idea/vcs.xml`을 부모 경로로 수정했다.
- PLEOS 확인: 앱이 처음에 PLEOS 기본 지도만 보여도 설치된 `MainActivity`가 실행 중일 수 있다. 앱을 다시 실행한 뒤 오른쪽 영역에 CARLOG 화면이 표시되는 것을 확인했다. 기존 빌드도 같은 지연을 보였으므로 새 레이아웃의 크래시로 판단하지 않는다.
- 기록: HTML 목업의 `주행 기록 / 숏폼 스튜디오` 탭을 분리하고, 최근 기록의 4장면 미리보기와 자동 일기·기록 상세 진입을 연결했다.
- 발견: 목업의 인기/친구/추천/방명록 분류를 추가했다. 세 피드 분류는 현재 데모 코스를 사용하며, 저장 코스 분류도 유지한다. 방명록은 샘플 글과 이 기기에만 저장되는 데모 글로 구성했다.
- 도감: 칭호 획득 수, 테마 미리보기, 첫 드라이브 챌린지 상태를 표시한다. 포인트 사용과 테마 획득은 연결 서비스가 없어 안내 문구만 제공한다.
- 검증: 최신 `:app:assembleDebug` 성공. PLEOS Connect에서 홈, 기록의 두 탭, 발견의 코스/방명록, 도감, MY가 표시되는 것을 캡처로 확인했다.
- 기록 추가: 최근 저장된 드라이브의 목적지·거리·시간으로 요약 카드와 3단계 장면 목록을 만들었다. 실제 센서 이벤트가 없는 데모 기록에 날씨·음성 이벤트를 임의로 붙이지 않았다.
