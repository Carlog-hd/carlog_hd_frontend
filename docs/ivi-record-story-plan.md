# CARLOG 기록·스토리 편집 개편

## 사용자 경험 목표

주행 기록은 거리만 저장하는 목록이 아니라, 주행 중 확보한 사진·동영상 조각을 모아 다시 보고 다듬을 수 있는 드라이브 스토리다. 정차 후 차량 화면이나 연결된 휴대폰에서 조각을 확인하고, 순서·길이를 편집해 하나의 초안을 미리본다.

## 현행 문제

- 기록 첫 화면의 ‘차가 기억한 순간’은 실제 캡처가 아닌 시작·거리·도착 문장이다.
- 같은 목적지로 반복한 시뮬레이션 기록이 목록에 여러 줄로 쌓인다.
- 미디어는 외부 문서 URI만 저장하므로 원본 접근 권한과 보관 위치에 의존한다.
- 로그 편집은 문구 입력 창에 한정되고, 초안 미리보기는 설명 문구만 표시한다.

## 순서와 완료 조건

1. **기록 첫 화면**: 최근 드라이브를 한 카드로 보여주고, 나머지는 목적지별로 묶는다. 실제 미디어 수를 표시한다. 캡처가 없으면 ‘아직 담긴 장면 없음’을 표시하고 가상의 순간 문장은 제거한다. 묶음 안의 각 주행은 선택해서 열 수 있어야 한다.
2. **저장 가능한 조각**: 사진·동영상을 선택하면 앱 전용 저장소에 복사하고, 기록별 순서·종류·동영상 원본 길이·선택한 시작/끝 시간을 저장한다. 기존 URI 기반 첨부도 읽을 수 있어야 한다. 제거·순서 변경·길이 조절은 즉시 저장한다.
3. **편집 화면**: 정차 상태의 기록 상세에서 조각 썸네일, 순서 조작, 삭제 버튼, 동영상 구간 선택, 문구 편집을 한곳에 둔다. 편집·저장 버튼으로 작업 상태를 분명히 한다.
4. **초안 미리보기**: 저장된 순서와 구간을 사용해 사진은 정해진 시간 동안, 동영상은 선택한 구간만 순차 재생한다. 빈 기록에는 미리보기 대신 장면 추가 안내를 표시한다.
5. **검증**: PLEOS 크기에서 첫 화면·편집·미리보기를 확인하고 앱 재시작 뒤에도 편집 결과가 남는지 확인한다.

## 진행

- 1단계 완료: 최근 기록 카드와 목적지별 묶음 목록을 PLEOS 에뮬레이터에서 확인했다. 실제 첨부가 없으면 빈 상태를 표시한다.
- 2~4단계 완료: 가져온 사진·영상을 앱 전용 저장소에 복사하고, 조각 순서·길이·문구를 기록별로 저장한다. 장면 타일과 미리보기를 구현했다. PLEOS에는 기본 파일 앱이 없어 앱 안의 미디어 목록을 제공한다. 샘플 장면 추가 버튼과 세로 스와이프 삭제는 사용자 요청에 따라 제거했다.
- 5단계 완료: PLEOS 에뮬레이터에서 장면 순서·사진 길이·영상 가져오기·영상 구간 선택·초안 재생 완료·앱 재시작 후 유지·편집/저장 버튼을 확인했다. 발견 화면의 카드를 3개에서 9개로 늘리고 새 카드 상세를 확인했다.
- 반포 스토리 예시: 기존 기본 시연 기록 하나를 `반포 한강대교 드라이브`로 바꾸고 사용자가 제공한 사진 3장을 편집 가능한 조각으로 한 번만 추가한다. 다른 기록의 목적지는 유지하며, 새 기본 시연 주행도 반포 이름을 사용한다.

## 연동 경계

현재 저장소에는 차량 카메라 캡처 API나 휴대폰 동기화 SDK가 연결되어 있지 않다. 이번 구현은 수집된 미디어가 들어온 뒤의 로컬 저장·편집·재생 경로를 완성한다. 자동 촬영과 휴대폰 전달은 각 연동이 정해진 뒤 구현한다. 최종 MP4 파일로 렌더링하는 기능은 아직 없다. 기존 JSON 백업은 주행 정보·코스·설정만 포함하며 미디어 파일과 스토리 편집 내용은 포함하지 않는다.
